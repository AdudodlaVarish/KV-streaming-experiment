# Prospective streaming-service experiment

Question: Can proactive growth admission plus deadline-aware service reduce client post-start interruptions under physical KV shortage, compared with the prior resume waiver and published TBT scheduling rules?

Freeze all parameters before diagnostic performance. Existing forced-length token-ID clients, models and CUDA runtime are reused unchanged. No output targets, remaining output counts, prompt-text predictor, or request.max_tokens are read by the experimental admission/priority logic. Native stopping uses the normal API limit. This is an empirical policy, not a guarantee under unbounded generation.

## Policies

- baseline: native FCFS, zero watermark.
- adaptive_resume: unchanged prior feedback reserve with preempted watermark waiver.
- slai_port: port the published SLAI core order: critical decodes by last schedulable time, active prefills, fresh prefills in shortest-prompt order, then noncritical decodes. Last schedulable time uses engine output time + .5 s minus twice the running mean dispatch-to-output batch delay. Active cap and decode cap match native concurrency. When a decode cannot append cache, evict an unscheduled fresh prefill, otherwise that decode itself, as in the public SLAI code. The pinned native body is transformed only to split its running phase around waiting admission and select that victim; all native output/async bookkeeping is preserved. Native prefix caching is off; one full-attention group; no speculative decode, encoder, connectors or LoRA. This is a same-engine core-policy port, not the original SLAI engine or a reproduction of its published performance. The async completion delay is a batch-time proxy, not CUDA kernel profiling. vLLM-specific adaptation: started preempted requests retain generated history and are queued by output deadline; native full-input feasibility and stale-output checks remain active. Resident active prefills follow prompt-length ties rather than SLAI's paused-prefill FCFS. Source: agrimUT/SLAI commit 5098a7aba05e3edbcfa3a509d6cc9cd248fc4380.
- growth_only: native FCFS with a rolling 128-position growth allowance per admitted stream. Before fresh admission, compute extra blocks needed for current known positions plus allowance, including unfinished prefills, summed over residents and the candidate. Deny if this exceeds free blocks, or any started request is paused. Resume does not require that extra allowance. Idle escape permits a physically fitting prompt even if its growth allowance would not fit.
- guard128: growth_only admission plus .5 s service target, native priority ordering by engine-output deadline, and one-budget protective credit for requests evicted within the past 1 s. Fresh requests follow already-started requests. After .25 s of silence for a paused started stream, hand off cache from at most one less-urgent native-safe resident per scheduling pass if cache or cap blocks its resumption. Native victim/preemption safety checks remain active. This is early corrective service, not a hard timer interrupt or guaranteed client deadline.
- guard256: identical, growth allowance 256.
- guard_fast / guard_relaxed: identical to guard128 with .25 / 1 s targets, used only on held-out long-tail workloads. Early handoff is half the selected target; repeat protection is one selected target for 1 s.

Policy clocks observe engine output callbacks, never the future client delivery time. All evaluation objectives use actual client token-ID delivery. Traces save native work/replay, output service, growth decisions, handoffs, admission attempts, requested/effective headroom, and first client delivery.

## Frozen matrix

96 retained trials / 1,152 requests; nine server configurations. Seeds 23 and 77 each shuffle four configurations: Llama 3.2 1B at 3,072 nominal KV slots/cap12 (balanced and generation-heavy mixes × clustered/staggered × six main policies: 48 total); Qwen 2.5 1.5B at 3,072/cap6 (generation-heavy × two arrivals × six policies: 24); Llama 12,288/cap12 relief controls (generation × two arrivals × baseline/guard128: eight); Llama 3,072/cap3 baseline controls (four). Held-out seed381 Llama 3,072/cap12 uses [128,256,512] prompt lengths and [64,256,1536] output targets, independently shuffled, × two arrivals × six stress policies: 12. The long tail exceeds both growth allowances. All requests finish normally; no rejection, timeout cancellation or output truncation is used to improve smoothness.

Twelve requests per workload; prior exact workload IDs for seeds23/77. Clustered arrivals have 50 ms spacing; stagger adds exponential .95 s mean intervals. BF16/eager/async FlashInfer, block16, prefix caching off, context/batch limit2048. Cache nominal Llama96/384MiB, Qwen84MiB. Two excluded warmups per process. Eight diagnostic trials are excluded. Objective native arrival-order verification must be 0..11. Preserve a whole failed configuration as excluded_order_* and repeat unchanged, retaining the first valid attempt, never performance-selecting. Stop after three invalid attempts.

## Measurements and audit

Primary: requests with client gaps >.5/1/2/5 s, worst client gap, total excess pause above1 s, and attainment of the selected service target. Also throughput, median/P95 TTFT/completion, per-request maximum gaps, native evictions, replay/lost computed positions, repeat victims, engine/client clock separation, and actual growth/handoff activity. Compare matched workloads, both seeds/models/arrival modes, the larger-cache controls, and the held-out long tail. Compare growth_only versus guard128 to isolate corrective scheduling; compare slai_port versus guard128 to compare deadline batching with capacity protection. Report every failure. Quantify incremental batching-gain retention against contemporaneous cap3 where available. No parameters are tuned on evaluation outcomes.

Verify full token delivery/usage and native success counts; preemptions equal native metrics; scheduled replay equals lost computed positions; no growing fresh admission violates its free-block inequality except documented idle escape; handoffs obey urgency and early-silence threshold; source hashes match the frozen code; native arrival order holds; servers stop. Same-machine Python perf_counter clocks, with bounded child reads, join traces to client deliveries. Scheduled positions and callback timings are not FLOPs/kernel execution measurements. Do not claim novelty or reproduce SLAI/CacheOPT/Chronos hard guarantees.
